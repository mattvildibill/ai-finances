## Session and completion boundaries

1. **Open the session.** The parent/manager reads current state, exact deployed revision, outstanding intents, source coverage and the previous handoff. Refresh and reconcile through the existing authenticated Site flow using a stable session idempotency key. An unresolved order or failed safeguard blocks new execution; research and diagnosis may continue independently.
2. **Assign distinct roles.** Give each agent a specific question, evidence cutoff, scope, deliverable and completion condition. Prefer independent initial assessments, then allow a focused response to concrete disagreement. Agents use public evidence and existing authorized tools; they do not establish new credentials or trading routes.
3. **Make one accountable decision.** The parent/manager considers the actual outputs, responds to material objections and records hold/buy/sell proposals through the supported schema. Only the parent-managed execution path can act, subject to every deterministic check. Agreement among agents is not a probability of success and cannot override a failed guard.
4. **Close the execution portion.** Read back actual results and reconcile any submitted intent before proposing another purchase. Preserve fills, losses, rejected orders and unfilled outcomes. A session may close with an unresolved issue and a no-new-orders instruction; never label an uncertain outcome settled.
5. **Start the bounded follow-through team.** After each session, delegate the distinct researcher, skeptical reviewer and portfolio-risk assignments below. Add the independent technical reviewer when code/site changes are proposed or completed. Each assignment ends with its specified evidence review, event response or handoff; it is not an endless process.
6. **Complete and hand off.** Once each assignment finishes, the manager appends the actual outputs and unresolved disagreements, reads them back, and records questions and triggers for the next scheduled review. At that next review, revalidate timestamps and state before using earlier findings. If a task cannot finish, preserve its partial result and exact missing evidence; do not fabricate completion.

Between sessions, “monitor” means bounded checks performed by available authorized runs and explicitly identified event-triggered follow-up. It does not imply a continuously running agent, an active subscription to every market event, or guaranteed notifications. Do not wait in infinite loops, spawn recursive reviewer trees, create competing orders, or add redundant scheduled runs. A failed or completed assignment returns to the manager. Reassignment requires a concrete new fact or unresolved question, not a request for agents to approve one another repeatedly.

## Event-driven follow-up and retained evidence

Concrete follow-up triggers include a scheduled earnings release, issuer/fund action notice, thesis-invalidating price or business fact, material source contradiction, changed mandate eligibility, reconciliation discrepancy, stale/failed feed, or a measured code/site failure. Specify the source to inspect and the question to resolve. If no supported event watcher exists, put the trigger on the next-session checklist and state that it is not continuously monitored. Newly discovered material information invalidates affected prior conclusions as required by the existing source/authorization contracts.

Retain each author's actual structured output, scope, timestamp, linked evidence and snapshot/record IDs. Record disagreements, corrections, limitations and manager responses. Append revisions with references to the originals; never rewrite original theses or replace dissent with a synthesized consensus. Store authored conclusions and evidence summaries, not private reasoning transcripts. Use stable idempotency keys and read back writes. Share short plain-English explanations of what changed, why it matters, what happened to the simulated money and what remains uncertain.

The next-session handoff must identify: last reconciled state and outstanding intents; actual decisions/outcomes; each completed or incomplete role assignment; changed thesis assumptions; unresolved objections; named watch events and whether they are actually monitored; remaining purchase/cash capacity from deterministic checks; exact code/release changes and verification status; and the next concrete review questions. No new information is a valid finding, not a reason to manufacture a trade.
